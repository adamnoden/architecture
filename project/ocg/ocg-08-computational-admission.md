## 1. Gate question

Does OCG now possess stable architectural authority that should be admitted to House Kernel / Metamorph Compiler or protected by OCG-specific regression locks?

The computational constitution is explicit:

- architecture is broader than computation;
- a pattern is not a compiler primitive merely because a Reference House selects it;
- representability is not evidence;
- missing/out-of-domain facts remain unsupported rather than guessed;
- deterministic output proves only the claims actually encoded.

OCG-07 made **no architectural change**. This gate therefore tests whether any new computational authority nevertheless exists.

---

# 2. What OCG can describe but should not formalise as one rule

The surviving synthesis is:

> **Change should be bounded.**

Technically, OCG asks whether the intervention consequence envelope is proportionate to the thing being changed and to the permanent burden of containing it.

That judgement spans:

- fabric disturbance;
- service interruption;
- occupied-function loss;
- contamination/work propagation;
- logistics;
- reinstatement/recovery;
- causal ownership;
- intervention frequency/foreseeability;
- permanent area/cost/carbon burden;
- fire/acoustic/moisture/thermal/structural duties;
- workmanship and architectural effect.

These are deliberately non-commensurable. Their synthesis is architectural judgement, not a stable scalar or Boolean invariant.

**Decision: `Change should be bounded` is not admitted as a universal compiler rule.**

# 4. Explicitly rejected computation

OCG rejects the following as misleading even if technically implementable:

1. **Disruption score** — collapses unlike consequence dimensions and hides value judgement.
2. **Renovability percentage** — creates false precision and invites optimisation to the metric.
3. **Predicted contractor duration** — architecture does not control programme strongly enough for generic deterministic claims.
4. **Dust/noise quantity from plan geometry alone** — depends materially on work method, tools, products and temporary controls.
5. **Contractor simulation** — outside House Kernel's architectural proof boundary.
6. **Automatic “occupied house remains habitable” verdict** — room/function criticality and safe occupation are intervention/project dependent.
7. **Machine-checkable access = maintainable/painless** — access is only one part of the complete intervention sequence.
8. **Automatic OCG pass/fail for the whole house** — violates the non-scalar consequence model and accepted-disruption controls.
9. **Speculative future-product compatibility** — exact future products/systems are unknown.
10. **Implicit promotion of held RH candidates** — compiler representation must not select architecture.

# 5. Compiler-stage decision

A new OCG compiler stage would require:

- stable accepted architectural propositions with controlled inputs;
- a domain whose failure semantics are explicit;
- a proof boundary that adds useful deterministic information;
- a reason existing plan/service/boundary/structural semantics cannot own the fact;
- evidence that the stage will not turn judgement into pseudo-certainty.

OCG satisfies none of these conditions for a distinct new domain.

The useful narrow facts are already conceptually owned by existing semantic layers or remain dependent on future product/site/MEP/detail inputs.

**Decision: no OCG compiler stage, no OCG semantic domain, no new compiler primitive.**

This is a negative admission result, not unfinished implementation.

---

# 6. Regression-lock decision

Regression locks protect accepted executable architectural authority from silent drift.

OCG-07 changed:

- no governing principle;
- no pattern;
- no RH geometry/topology/detail;
- no compiler source;
- no drawing;
- no delivery requirement.

Therefore there is no newly accepted OCG architectural fact that could silently regress in code.

Adding OCG-specific tests merely to prove OCG exists would duplicate current source/output/regression checks and create a false executable authority surface.

**Decision: no OCG-specific regression locks.**

Existing regressions continue to protect the underlying selected RH facts OCG consumed.

If a future owner later admits a controlled removal route, isolation dependency or clearance method, that owner's packet must add the smallest regression appropriate to **that accepted fact**, not revive a generic OCG test suite.

---

# 7. Proof-boundary statement

OCG may continue to use computational outputs as evidence where they already prove bounded source relationships, for example:

- declared spatial adjacency;
- route/node topology;
- registered structural/service crossings;
- boundary obligations;
- deterministic source identity.

But OCG must preserve this chain:

`controlled source fact → bounded computational assertion → human OCG consequence interpretation`

and must never reverse it into:

`OCG desired outcome → invented compiler fact → apparent proof`.
