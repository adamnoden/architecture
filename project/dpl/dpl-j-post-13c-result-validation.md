## Decision

> **PASS — DPL-13C EARNS CONTROLLED M4 AUTHORITY FOR THE CANONICAL DPL-RS-01 WHOLE-SITE `UNRESOLVED @ SCREENING` RESULT. KEEP `COMPATIBLE`, `INCOMPATIBLE`, ROUTE EXHAUSTION AND GENERIC WHOLE-SITE RESULT AUTHORITY HELD. BEFORE ANY POSITIVE-CONTROL WORK, REQUIRE ONE BOUNDED DPL-13C.1 SEMANTIC-HARDENING PACKET.**

The important scope qualifier is **canonical**.

DPL-13C is internally controlled for the exact current Reference House × DPL-RS-01 case and its declared SCREENING owner universe. DPL-J does **not** validate a generic result algebra for arbitrary future target compositions, sites or obligation histories.

Two generic seams exposed by the red team are real but do not falsify the canonical result:

1. the only explicit planning obligation join is conceptually target-specific but the current implementation locates the obligation by `obligationId` alone rather than the exact `(targetId, obligationId)` pair;
2. generic `WARNING` and `SUPERSEDED` branches in `obligationState()` are both mapped to substantive unresolved, while DPL-03 says warnings do not block a deployment conclusion and superseded results must not participate as current authority.

Neither seam is exercised by the canonical current London D3 result, which is exactly one current `UNRESOLVED` obligation under the single controlled London strategic target. They therefore do not invalidate the canonical `UNRESOLVED @ SCREENING` conclusion. They **do** block broadening the proposition into generic or positive-result authority.

The exact next packet is therefore DPL-13C.1, not positive compatibility.

## 2. Coverage → substantive joins

### DPL-02 exact clause join — PASS

Reference House entries use exact `ownerEntryId === finding.clauseId` matching against the current DPL-12B candidate-conformance ledger.

This correctly preserves:

- native `CONFORMS` findings as positive at their exact clause scope;
- non-native `OPEN` findings as substantive unresolved;
- non-conformance / Reference House revision requirements as substantive failures that still do not imply whole-site site incompatibility.

Coverage presence never becomes conformance.

### London D3 join — PASS for canonical case; generic hardening required

The canonical planning family:

```text
PLANNING:DPL10-COV-STRATEGIC-DESIGN-CONTEXT-CAPACITY
```

maps only to:

```text
LON-D3-DESIGN-LED
```

and the resulting record correctly identifies the actual target as:

```text
LON-STRATEGIC-RESIDENTIAL-DESIGN-2021-2026-10-20:LON-D3-DESIGN-LED
```

The canonical D3 obligation is current and `UNRESOLVED`, so the current result is correct.

However the implementation's lookup searches by `obligationId` alone after the mapping table names only the obligation id. `DeploymentObligationLedgerEntry` explicitly carries both `targetId` and `obligationId`; no generic authority establishes obligation ids as globally unique across every future target composition.

Therefore DPL-13C.1 must replace this with an exact `(targetId, obligationId)` mapping and fail closed on zero or multiple matches.

This is a generic identity-hardening defect, not a canonical-result defect.

### Unimplemented case-specific evaluators — PASS

For a due-now owner family with no admitted exact substantive join, DPL-13C emits:

```text

NO_CASE_SPECIFIC_SUBSTANTIVE_FINDING
SUBSTANTIVE_UNRESOLVED
```

That is conservative and correct. Absence of implementation does not become absence from scope or a pass.

### Synthetic facts versus external evidence — PASS

No synthetic site claim is converted into title, flood, survey, access, planning judgement, provider or professional evidence discharge.

This is particularly important for the DPL-11 due-now families and is preserved.

## 5. `UNRESOLVED @ SCREENING` admission semantics

### Verdict: PASS

The canonical result is not emitted merely because DPL-RS-01 contains unknowns.

It requires all of:

1. complete DPL-13B owner/site universe;
2. complete current blocker key set;
3. exact case/readiness identity composition;
4. at least one non-positive current blocking record;
5. explicit substantive or classification state for every blocker;
6. separate future-due set;
7. no route-exhaustion claim;
8. no positive/incompatible result authority.

The adversarial fixtures prove:

- incomplete owner universe → no conclusion;
- missing blocking record → no conclusion;
- complete all-positive record set → no positive conclusion;
- hard failure without route exhaustion → still only `UNRESOLVED`.

This is consistent with DPL-03:

> `UNRESOLVED` is the correct deployment conclusion whenever positive compatibility has not been earned and incompatibility has not been proved.

## 9. DPL-03 semantic audit: one bounded generic repair

DPL-J found a second generic branch debt in `obligationState()`.

Current DPL-13C groups:

```text
UNRESOLVED
WARNING
SUPERSEDED
```

into `SUBSTANTIVE_UNRESOLVED`.

DPL-03 is more precise:

### `WARNING`

> The represented state is valid at the mandatory level but departs from a preference, quality target or recommended condition.

> Warnings do not block a deployment conclusion unless the underlying source is later promoted into a mandatory obligation.

A bare warning must therefore not become a substantive blocker simply because an exact mapped obligation happens to return `WARNING`.

### `SUPERSEDED`

> A superseded result must not participate in the current deployment conclusion.

A superseded historical result may cause the current proposition to remain unresolved **because current authority is absent**, but the historical result itself must not be treated as the current substantive blocker.

Neither branch is exercised by the canonical current D3 mapping, which is `UNRESOLVED`. The canonical result therefore survives.

DPL-13C.1 must harden these branches and add adversarial regression tests before positive-control work.

After DPL-13C.1, run a fresh gate before opening a positive-control fixture or positive-result implementation.
