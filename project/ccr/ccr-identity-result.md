## Reproduced counterexample and actual consumer need

On the integrated compiler, changing the first runtime service route's destination from `G-PLANT-01` while holding source, method, statuses and selected summary fields fixed leaves the compact compile fingerprint unchanged. Rendering that controlled perturbation changes the actual service-register bytes and its output-manifest SHA-256 identity. The other five outputs remain unchanged in this particular experiment.

This is a coverage boundary, not a SHA-256 collision. The altered runtime object is a deliberate probe, not a newly validated source or an admitted architectural design. The compact identity was already documented as selected semantic fields. No inspected consumer requires equality of all runtime objects or implementation bytes; adding such a guarantee would change the contract without a demonstrated need. This packet instead makes the limitation explicit where identities are produced, associated and read, and protects it with meaningful perturbation tests.
