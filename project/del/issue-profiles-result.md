# DEL-ISSUE-PROFILES — purpose-specific information contract

**Outcome:** complete at issue-requirements scope, 29 October 2026.
Owning issue: [DEL #854](https://github.com/adamnoden/architecture/issues/854).
Deliverable: [information issue profiles](../../docs/delivery/information-issue-profiles.md).
This completes the requirements packet, not a real commission, review,
construction issue, information-production engine or handover.

The owner-house charter, DEL delivery plan and brief, existing delivery modules,
ADE construction-information contract and compiler-target separation control this
result. The requirements name the decision an issue supports rather than using a
single document-completeness label for every stage.

## Delivered contract

- Six profiles cover concept review, planning preparation, coordinated technical
  review, tender/pricing, construction issue and as-built/maintenance handover.
  Each names audience, documents/registers, evidence/acceptance, tolerable
  unknowns and accountable issuing responsibilities.
- A common issue record binds scope, source/document/issue revisions, evidence,
  decisions, unknowns, review/authorisation and distribution. Restricted evidence
  can remain private with a controlled accessible reference.
- Machine completeness, design/evidence disposition, actual review authority and
  permitted use remain independent. ADE receives a bounded implementation
  contract, not an instruction to build a universal approval engine.
- The worked wet-suite example pins actual HAD/IAS/BCR/current-house information
  to immutable main `04212ccdddab5a56b0599061cc6724444e409a08`. It is valid bounded
  technical-review information with explicit missing installation/support
  questions, but invalid for construction release using the same information.
  No external review or issue is represented as having occurred.
- Normative compiler targets, supported methods, project facts and issue purposes
  remain distinct. Actual submission requirements, appointments and approvals
  must be established for the real project; the profiles do not create them.

## Acceptance and downstream handoff

The six-purpose matrix and worked example satisfy the owning packet contract.
The common record applies the revision/evidence basis to every profile. Missing
essential design evidence cannot be disguised as a contractor verification note,
a provisional price or a complete schedule. Formal specialist responsibilities
and hold points must state which work is not released.

ADE-DETAILS/SCHEDULES/EVIDENCE implement only the selected bay's necessary checks;
DEL-BAY-PACK assembles the review issue; EPR obtains actual competent responses.
The later commission plan allocates real participants and project-specific
submission, procurement, construction and handover authority. DEL #854 remains
open and delivery maturity is unchanged.

Validation uses repository/link integrity, project-control checks, TypeScript and
site build, plus independent review of the profile/authority distinctions and
worked example. Exact validation and merge identities are recorded in the PR;
this source does not claim an unperformed professional review or physical test.
