No new engine, house model, construction detail, schedule or issue approval is implemented by this audit.

## The actual information problem

The [bay brief](../bcr/bay-brief-result.md) selects `BAY-FRONT-STUDY-01`: **GROUND / outer-south / south-window-0**, the front study window and its wall, ground-floor and intermediate-floor interfaces. The whole furnished study and connected approach remain part of the operation/renewal question beyond the drawing crop. The bare opening ID is insufficient because it recurs on the first floor. The brief owns the coordinates, conventional OAS control, required actions and exclusions; this audit does not copy a second geometric model.

The first package is a coordinated technical review under **IP-03** in the [issue profiles](../../docs/delivery/information-issue-profiles.md). Its purpose is to expose a selected, internally coherent construction study and its exact unresolved evidence questions to competent reviewers. It is not IP-05 construction release. Record completeness, design/evidence disposition, review authority and permitted use remain separate. A repository commit, a successful compile and a complete drawing index cannot supply an appointed designer, a test or permission to construct.

The material gap is not the ability to draw a window. It is a common selected basis linking that window's actual support, boundaries, components, tasks and evidence across the package. Current nominal OAS details and house representations are useful inputs, but they do not yet establish that connected selected assembly.

## Smallest implementation contract and file ownership

This is the receiving contract for later packets, not a newly implemented schema. A current source adapter plus small typed records is enough unless actual use demonstrates otherwise.

1. **ADE-MODEL, after HRS-TECHNICAL:** establish one read-only bay view over admitted current source. Use a project/bay identity plus level/host/opening identity and explicit assembly/component IDs. Reference authoritative geometry; do not retype it into a drawing, schedule or second fixture. Preserve selected/candidate/unresolved state, units, datums and source revision. The bay adapter must reject a missing, renamed or ambiguous object. Adopted assembly/specification records are inputs owned by their design authors, not defaults inside the renderer.
2. **Separate output owners after the shared contract:** ADE-DETAILS consumes that view for drawings/action sheets; ADE-SCHEDULES consumes it for rows and justified quantities. Proposed paths are a bounded `compiler/reference-house/construction-bay/` adapter and separate `details`, `schedules` and `evidence` modules only if these additions are needed. Preserve historical adapters and output paths. Final filenames are implementation choices, not existing capabilities. Shared contract changes return to ADE-MODEL; concurrent output workers must not redefine it independently.
3. **ADE-EVIDENCE:** bind each required claim to actual controlling object/field values, method/product/document edition, result, scope/limitations and responsible evidence source. Distinguish a data/content digest from a semantic dependency guarantee. Missing evidence prevents a stronger claim; unsupported computation is reported. Controlled external calculations and reviewed drawings need not be reimplemented in this repository. Private evidence uses a controlled reference/custodian and authorised recipient access, as DEL requires.
4. **DEL-BAY-PACK:** compose the common issue/index from the actual outputs and references. Keep machine completeness, design/evidence status, human review and permitted use separate. Do not overload `OutputManifest.status` or add “construction approved” to a drawing's metadata. A static, reviewed index may suffice; implement a small validator only for repeated concrete consistency duties.

No-change and external-tool outcomes are legitimate: keep the vector backend and orthogonal topology unchanged; retain an authoritative specialist detail/specification rather than tracing it into an invented generic model; use existing Markdown/JSON records for non-spatial data; omit a bespoke component or quantity generator if the conventional design and controlled external schedule already meet the declared duty. Conversely, a manual table is not a substitute for reproducible change coordination where the admitted ADE packet promises it. Record the actual route and prove its consistency.

## What later implementation must demonstrate

| Controlled change / adverse case | Required evidence |
|---|---|
| Change the selected opening width, sill/head or frame/assembly data | Located plan/elevation/section, dimensions and relevant schedule/quantity rows agree. A selected product that no longer fits becomes an explicit conflict; it is not silently rescaled |
| Remove/rename the bay opening or a scheduled component; reuse a bare opening ID from the other level | Reference resolution rejects the missing/ambiguous object before producing an apparently complete package |
| Change a controlling support, fixing, boundary or product input | The actually dependent calculation/review/test applicability becomes pending/stale for reassessment. Unrelated evidence remains current only under its declared dependency scope |
| Change only a label layout or sheet presentation | Artifact/content identity changes, while unchanged design/evidence dependencies are not falsely invalidated; publication legibility/scale checks still apply |
| Supply missing evidence, a mismatched external revision or unresolved essential design | The register exposes the precise deficiency and affected claim. IP-03 may frame it as a question; IP-05 cannot acquire construction authority from record completeness |
| Regenerate the accepted candidate and inspect physical-scale output | Deterministic bytes or declared versioned change, correct cross-references, fonts, dimensions, scale and visual legibility. Inspect the whole action route and boundary continuations, not only the crop |

These are acceptance obligations for ADE-MODEL/DETAILS/SCHEDULES/EVIDENCE, not tests claimed to have run on an implemented bay package. No whole-house BoQ, IFC/DWG exchange, arbitrary CAD, universal approval engine or new engineering solver is earned by this audit. The actual commissioned team's information needs may later justify a different controlled route.
