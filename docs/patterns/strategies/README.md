# Strategies

Strategies are broad architectural approaches that can be realised through materially different patterns or implementation families.

They sit between governing doctrine and the pattern language, but they are **not pattern nodes** and do not receive `HSA-P-xxx` identities.

A strategy belongs here when its durable proposition is useful but its valid physical responses are too different to represent one recurring architectural relationship.

Current canonical strategy set:

- [Fail-Safe Water Distribution](fail-safe-water-distribution.md)
- [Decompose Structural Interface Functions](decompose-structural-interface-functions.md)
- [Separate Structural Floor from Changeable Layers Where Proportionate](separate-structural-floor-changeable-layers.md)

The strategy set is intentionally small. Do not create a strategy merely as a category heading for several patterns.

See the [Pattern Language Model](../language-model.md) and [Phase 7 Migration Plan](../../development/pattern-language-phase7-plan.md) for the classification rules.
