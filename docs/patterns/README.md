# Patterns

This area holds reusable architectural responses developed from the doctrine.

The project is currently testing a move from a **pattern catalogue** to an evidence-qualified **pattern language**: stable pattern identities, sparse typed relationships and generative sequences that help decide when and in what order patterns should be applied.

The migration is deliberately gated. The existing [Core Pattern Catalogue](core-12.md) remains the developed pattern prose while the language mechanics are tested against the Reference House. Do not duplicate or migrate the full catalogue until that gate passes.

Start with:

- [Pattern Language — Model and Authoring Contract](language-model.md) — what counts as a pattern and how the language works;
- [Service-Topology Pilot](pilot/README.md) — six linked pilot pattern records;
- [Service Topology — Generative Sequence](service-topology-sequence.md) — first sequence and rewind logic;
- [Core Pattern Catalogue](core-12.md) — current developed pattern prose;
- [Ground-Supported Façade Access](ground-supported-facade-access.md) — specialised developed pattern;
- [Reversible Assembly Candidates](reversible-assembly-candidates.md) — high-value but unproven construction propositions.

Patterns carry their own evidence, maturity, forces, trade-offs and failure modes. Location here never implies validation.

The migration programme and stop rules live in [`../development/pattern-language-overhaul.md`](../development/pattern-language-overhaul.md).
