# Working documents

This directory separates the project's **source material**, **active publication**, **pattern system**, **research record** and **delivery tools**.

## Authority and status

### `source/`
Preserved source corpus.

- `house-design-doctrine-v7.md` is the authoritative v7 doctrine supplied at the start of the professional-publication exercise.
- Treat it as immutable source material unless explicitly creating a corrected archival revision.
- It is **not** the current publication manuscript.

### `manuscript/`
Current publication work.

- `governing-principles.md` — ten-principle lock candidate.
- `publication-architecture.md` — structural lock candidate for the book.
- `part-i.md`, `part-ii.md` — active prose drafts.

When continuing the book, these are the primary files to work against.

### `patterns/`
Controlled architectural responses.

- `register.md` records evidence status, maturity and required proof.
- `core-12.md` contains the first patterns developed as publication-ready candidates.

Patterns are not doctrine. A pattern may be rejected without invalidating the governing principle it serves.

### `research/`
The audit trail.

Contains the v7 editorial audit and traceability, 63→10 principle mapping, evidence/lineage work, claim dossiers, precedent shortlist and professional red-team.

Use these files when checking why a claim exists, how strong it is, or what prior criticism must not be lost.

### `delivery/`
How the ideas become professional architectural work.

- `figure-programme.md` defines the conceptual drawing set.
- `riba-implementation-brief-template.md` is the project-team translation layer.

### `work-register.md`
The live checkpoint. Update it whenever a meaningful phase changes.

## Editorial conventions

1. **Do not promote a reference-house choice into doctrine without an argument.**
2. **Do not promote a pattern because it is visually attractive.** Record evidence and maturity separately.
3. Every unusual serviceability provision must pass a proportionality test: frequency × consequence × retrofit difficulty versus permanent cost, carbon, material and spatial burden.
4. Every opening, void or removable element carries **boundary debt**. Check structure, fire/smoke, acoustics, air, vapour, water, thermal continuity, pests and security as applicable.
5. Distinguish maintenance access, component replacement and eventual disassembly/recovery.
6. Preserve rejected options and counterexamples. The publication should demonstrate judgement rather than inevitability.
7. Prefer ordinary components and fabrication methods; concentrate invention at the arrangement and interface.
8. Keep citations/evidence claims traceable to the research files.
9. Use the reference house as a worked interpretation and research vehicle, not as proof that the doctrine is correct.
10. Update `work-register.md` before ending a substantial work session.
