# Reference House — Pattern Occurrence Register

**Status:** canonical Reference House project-state register  
**Purpose:** distinguish patterns selected in principle from actual project occurrences, implementation directions and outstanding evidence obligations.

The Reference House is a worked interpretation of House Kernel. It is **not evidence for the pattern language**.

A House Kernel pattern appears here as a current occurrence only when the active house has enough geometry or information to identify what the occurrence actually is. A pattern may be relevant or selected in principle without yet having an occurrence.

## Current transition state

`RH-01 — Test the gross morphology` removed the F0 room/service geometry. `RH-02 — Resolve ground-floor order` has now established a new 12.0 × 10.8 m ground-floor baseline around the same 3.6 × 4.0 m courtyard, including a dedicated service block, inner gallery and kitchen edge.

The old F0 identifiers remain suspended provenance. RH-02 issues new occurrence identities where the new project object is geometrically distinct.

See [RH-02 Ground-Floor Development](ground-floor-development.md), [RH-01 Gross Morphology Options](morphology-options.md) and the [Brief and Constraint Ledger](brief-and-constraint-ledger.md).

## 3. Selected strategies

Strategies are not pattern occurrences and receive no `RH-Pxxx-*` identity.

### Fail-Safe Water Distribution

The house continues to select [Fail-Safe Water Distribution](../patterns/strategies/fail-safe-water-distribution.md) as its water-failure strategy.

The route-class interpretation remains useful as a design brief; detailed routes are not yet re-established:

- `WF-01` plant/manifold geography — accessible joints, isolation, visible/manageable leakage and optional sensing;
- `WF-02` concealed vertical pressurised-water run — joint-minimised route, pipe-in-pipe/withdrawable option, leakage made detectable at an accessible point;
- `WF-03` kitchen/utility branches — short routes with joints/isolation in accessible service geography;
- `WF-04` bathroom branches — dry-side access where practical, joint-minimised concealed finals, waterproofing as a separate boundary;
- `WF-05` soil/waste — accessible stack/base/rodding and short gravity branches.

This selection does **not** mean every child pattern or implementation has been selected. In particular, manifold distribution remains a held candidate and pipe-in-pipe remains an implementation family.

### Structural / floor strategies

[Decompose Structural Interface Functions](../patterns/strategies/decompose-structural-interface-functions.md) and [Separate Structural Floor from Changeable Layers Where Proportionate](../patterns/strategies/separate-structural-floor-changeable-layers.md) remain project-relevant design strategies, but the Reference House has not yet resolved enough structural/floor geometry to record worked implementation decisions against them.

## 7. Rejected / rewound moves that remain part of the design record

Earlier whole-house coordination rejected four tempting local solutions. Their **reasons** remain live even though the F0 locations do not:

1. **universal mixed-services horizontal duct** — service-specific routes remain preferred to one oversized mixed-services void;
2. **scattered upper wet rooms without route justification** — RH-03 should test clustering before accepting long gravity/ventilation branches or duplicate vertical routes; the old east/rear location is not retained;
3. **plant hidden in ordinary kitchen cabinetry** — `G-SVC-02` now gives this rule a new geometric home, subject to RH-06 proving it;
4. **blanket leak containment everywhere** — retain route-class-specific failure responses under Fail-Safe Water Distribution.

RH-02 adds two further rejected moves:

5. **courtyard crossing as the only ordinary front-to-rear route** — architectural sequence may use the court, but daily circulation should not depend on weather exposure;
6. **one undifferentiated rear great room as the default solution to contemporary family life** — linked rooms are preferred while they remain functionally convincing and structurally proportionate.

These decisions remain part of the design record unless later evidence justifies reopening them.

## 8. Update rule

Update this register when:

- RH-03 creates enough upper-floor geometry to re-instantiate wet-room / vertical-service occurrences;
- an occurrence moves, splits, merges, is suspended or rejected;
- an implementation family is selected or abandoned;
- a strategy changes;
- new evidence invalidates an occurrence;
- a held candidate is promoted/rejected at project or language level;
- a rewind changes upstream architecture.

When an old identifier is re-used, ensure the underlying occurrence is recognisably the same project object; otherwise issue a new occurrence identity and leave the old one as provenance.

Do not update pattern evidence or maturity merely because this house uses a pattern.
