# 3. Findings

Use one row per material finding.

| ID | Classification | Current project assumption | Finding / evidence | Consequence if unchanged | Smallest credible correction | RH gate / object made stale | Evidence required to close |
|---|---|---|---|---|---|---|---|
| `REV-__-01` | CONFIRM / QUALIFY / MATERIAL FINDING / REWIND / OUTSIDE SCOPE |  |  |  |  |  |  |

### Classification meanings

**CONFIRM** — technically credible at current scope.  
**QUALIFY** — credible direction but scope/dimension/dependency should narrow.  
**MATERIAL FINDING** — current assumption cannot safely proceed unchanged.  
**REWIND** — finding invalidates an architectural/system decision owned by an earlier RH gate.  
**OUTSIDE SCOPE** — another discipline / real site / test owns the question.

For `MATERIAL FINDING` and `REWIND`, identify the affected project object wherever possible: e.g. `SV-01`, `G-PLANT-01`, `EB-W-S`, `OW-01`, `ASHP-01`, `PEN-*`, `RH-P*`.

# 4. Missing information

List information that is genuinely required before your discipline can progress.

Distinguish:

- **technical-design input** — can be produced without changing the architecture;
- **site input** — impossible to know before a real site exists;
- **cross-discipline input** — another reviewer owns it;
- **architectural omission** — would require RH gate reopen.

Do not classify normal downstream calculations as architectural failures merely because they do not exist yet.

---

# 5. Red-team cases

Provide at least **two plausible ordinary cases** that would break or materially stress the current design assumption.

For each:

```text
case
→ what fails first
→ how the failure becomes visible
→ smallest response
→ whether an RH rewind is required
```

Prefer ordinary adverse cases over exotic edge cases.

# 6. What should remain unchanged

Identify any current decisions that are technically useful enough that later design should avoid casually reopening them.

This section matters because external review is intended to narrow uncertainty, not create indiscriminate design churn.
