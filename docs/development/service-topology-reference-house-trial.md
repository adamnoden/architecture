# Pattern-Language Pilot — Reference-House Trial 01

**Status:** historical Phase-5 trial — superseded by completed Phase 5–8 work  
**Sequence tested at the time:** the service-topology pilot that preceded the current [canonical sequence](../patterns/service-topology-sequence.md)  
**Current project state:** [Reference House Pattern Occurrence Register](../reference-house/pattern-occurrence-register.md)

> **Historical record.** This trial captured the first honest failure to run the service-topology sequence against an underdeveloped Reference House. Its findings were subsequently acted on: whole-house coordination geometry was created; vertical distribution became canonical `HSA-P-014 — Accessible Vertical Service Zone`; `HSA-P-003` became **Coherent Horizontal Service Route**; water-failure material was reclassified under the **Fail-Safe Water Distribution** strategy; the Reference House now has explicit project occurrences; and Phases 6–8 have passed. The body below is preserved as the Phase-5 reasoning that produced those outcomes. Statements such as “current state”, “required decision” and “next gate” refer to that historical trial.

## Purpose

Test whether the new pattern language and generative sequence produce useful project information when applied to the actual Reference House, rather than merely making the pattern catalogue more elaborate.

This trial does **not** invent missing house geometry in order to make the migration look successful.

---

## Result

**The sequence is useful, but the Phase 5 exit gate is not yet passed.**

The existing Reference House is developed strongly at tectonic and representative-bay scale but is not yet a complete house plan/site/service coordination model. The service sequence therefore cannot be run to completion honestly.

That limitation is itself useful. The existing vertical-bay document says the preferred service topology is:

- horizontal services biased toward corridor / service spines;
- room distribution in skirting or wall-side zones;
- planned vertical routes;
- larger ducts and drainage in deeper dedicated zones.

The sequence converts those sound but broad intentions into a concrete set of house-scale decisions that the current Reference House has not yet made.

---

# Step-by-step trial

## S1 — Map service demand

**Current state:** partial / implicit.

The project understands service-heavy spaces conceptually, but the current Reference House material does not yet contain a complete room schedule or house plan on which water, drainage, ventilation, electrical and maintenance demand nodes can be mapped.

**Finding:** sequence adds value. It makes clear that the next services task is **not drawing routes**; it is producing a demand-node map on the actual house plan.

**Required artefact:** Reference House service-demand overlay once the plan is sufficiently defined.

---

## S2 — Controlled utility entry (`HSA-P-001`)

**Current state:** pattern direction exists; project occurrence does not.

The Core Pattern Catalogue suggests a side/rear intake zone beside the plant/service hub, but the Reference House material reviewed does not yet establish the actual site-side utility approach or boundary crossing.

**Finding:** the pattern can be stated, but the house cannot yet claim to use it.

**Required decision:** utility approach and entry zone coordinated with site access, external maintenance, envelope and future plant replacement.

---

## S3 — Plant Room as Service Hub (`HSA-P-002`)

**Current state:** pattern direction exists; project occurrence does not.

The project strongly favours a service hub, but the current Reference House does not yet show its actual location, working clearances, replacement route, drainage or relationship to the external door/site.

**Finding:** the sequence exposes the difference between **having a doctrine preference** and **having a project occurrence**.

**Required decision:** place and dimension the actual hub before the whole-house plan is frozen.

---

## S4 — Vertical distribution

**Current state:** explicitly acknowledged but unresolved.

The vertical-bay coordination says “planned vertical routes” but does not define the house-scale route.

**Finding:** **confirmed language gap.**

The sequence has found reusable design knowledge that is important enough to the Reference House to appear in its preferred topology but has no current pattern record.

This is stronger evidence for developing a Vertical Service Riser candidate than the publication outline alone.

**Required research before pattern admission:**

- proportionate domestic riser geometry;
- relation to high-service-room stacking;
- access and replacement value;
- fire/acoustic cavity closure;
- drainage and duct depth;
- interaction with permanent structure;
- alternatives where a dedicated riser is unnecessary.

Do not assign an ID yet.

---

## S5 — High-Service-Room Service Wall (`HSA-P-004`)

**Current state:** not yet testable at house scale.

The project has a developed reusable response, but the current Reference House material does not yet establish bathroom/kitchen/utility adjacencies strongly enough to show where one or two service walls would do substantial work.

**Finding:** the sequence creates a useful **rewind criterion** for the future plan.

If service-wall logic only works by adding separate technical walls to every wet room, first reconsider room stacking and adjacency.

That is a materially stronger instruction than “use service walls where possible”.

---

## S6 — Horizontal Service Spine (`HSA-P-003`)

**Current state:** principle present; occurrence unresolved.

The vertical-bay study explicitly prefers corridor/service spines, so the pattern is compatible with current reference-house thinking.

But no complete plan currently demonstrates route continuity, required depth, duct/drainage feasibility, access intervals or interaction with principal rooms.

**Finding:** the pattern has a genuine house-scale role, but the phrase “service spine” is currently doing more conceptual work than the Reference House geometry has earned.

**Required artefact:** one coordinated plan/section route overlay showing actual primary horizontal distribution.

---

## S7 — Designed Structural Penetration (`HSA-P-005`)

**Current state:** conceptually well aligned; no whole-house schedule.

The vertical-bay work already protects the joist zone from routine service distribution and treats crossings/boundaries as explicit obligations.

**Finding:** this pattern appears to be correctly classified. It becomes meaningful **after** topology is known and should not drive route geometry by itself.

**Required artefact:** controlled penetration schedule derived from the selected service routes and structural scheme.

---

## S8 — Water failure strategy

**Current state:** doctrine and local concerns exist; classification remains unresolved.

The vertical-bay study requires water-bearing joints not to leak unseen and keeps external wetting/drainage independent of decorative lining. That supports the governing strategy.

It does not establish that the current Core Pattern 06 is one coherent architectural pattern.

**Finding:** **classification concern strengthened.**

At house scale the question is first “what failure performance does this route need?”; only then do different physical responses such as accessible distribution, pipe-in-pipe or local containment make sense.

Current recommendation: treat `Water-Damage-Safe Service Route` as **strategy pending full-house test**, not a locked pattern identity.

---

## S9 — Physical Service Index (`HSA-P-012`)

**Current state:** compatible but not yet instantiated.

The Reference House has a strong tectonic language for durable labels/indexes and visible brass/bronze where something indexes or comes apart. The physical-service-index pattern fits that language well.

**Finding:** correct stewardship-scale pattern; sequence placement is useful because it prevents the index from becoming an attempt to explain an incoherent system after the fact.

**Required decision:** define stable identifier scheme once the house-scale service topology is real.

# What the language pilot has exposed

## 1. A real missing pattern candidate

**Vertical service distribution / riser** is no longer just a line item in the publication outline. The Reference House already assumes planned vertical routes, and the generative sequence cannot connect building-scale plant to room-scale distribution without resolving them.

That is precisely the kind of gap a pattern language should expose.

## 2. A likely misclassified existing pattern

**Water-Damage-Safe Service Route** currently looks more like a strategy or performance objective than one recurring physical relationship. Keep this provisional until the complete-house service topology is drawn.

## 3. The graph and sequence do different jobs

The trial confirms the distinction.

`HSA-P-004` conceptually **completes** `HSA-P-003` at a finer scale, but the sequence asks the designer to examine service-wall opportunities before finalising the horizontal spine because room adjacency is expensive to change later.

A single dependency graph would express this badly.

## 4. The reference house needs explicit pattern occurrences

Current documents often say what the house **prefers**. The language model forces a useful distinction between:

- pattern exists;
- project intends to consider pattern;
- project has selected pattern;
- occurrence has actual geometry;
- occurrence has selected implementation family;
- occurrence has evidence.

This should become part of Reference House coordination later.

## 5. Rewind conditions are genuinely valuable

The strongest new design information is not the ordering itself but the instruction to change upstream architecture when downstream service complexity is signalling a bad earlier choice.

Examples now made explicit:

- scattered wet rooms → revisit adjacency before multiplying service walls;
- excessive route depth → revisit hub/vertical/room organisation before creating a large technical void;
- many bespoke structural crossings → revisit the route before detailing more penetrations;
- elaborate leak containment everywhere → revisit where water is being routed.

This is a substantive gain over the current catalogue.

---

# Phase 5 gate decision

**Do not authorise full corpus migration yet.**

The language mechanics have produced useful information, but the current Reference House is not geometrically complete enough to prove that the six pilot patterns and sequence compose across a whole ordinary house.

The next architectural work should not be more taxonomy. It should advance the Reference House just enough to run the service sequence honestly.

Minimum package required to close Phase 5:

1. provisional whole-house plan and storey relationships;
2. high-service-room / demand-node overlay;
3. utility-entry and plant-hub occurrence;
4. explicit vertical distribution proposal;
5. horizontal primary route proposal;
6. service-wall opportunities and rejected locations;
7. representative crossing schedule;
8. water-failure strategy applied to those real routes.

Once that package exists, rerun this trial and decide whether Phase 6 — full corpus audit — is authorised.

---

# Migration recommendation

Continue the overhaul, but **hold the full migration at its designed gate**.

Phases 0–4 have already justified the method sufficiently to keep the new architecture. Phase 5 should now merge with the existing high-priority task of completing the Reference House rather than spawning more pattern-language paperwork.
