# Tectonic Migration Plan

**Status:** historical migration plan — completed; retained as provenance  
**Branch at the time:** `tectonic-honesty`  
**Baseline:** `main` at the start of the migration  
**Rule:** `docs/source/house-design-doctrine-v7.md` remains historical source material and is not rewritten in place.

> **Current authority:** the migration described below has been completed and subsequently refined by the canonical pattern language, current [Tectonic Integration Register](tectonic-integration-register.md), [Reference House occurrence register](../reference-house/pattern-occurrence-register.md) and prototype programme. The phase descriptions below are preserved as the plan that organised the work; old candidate names and classifications are historical, not current HSA authority.

## Objective

Integrate the new tectonic and reversible-assembly thinking without turning the project into a collection of disconnected clever details.

The migration must preserve the publication's hierarchy:

**Doctrine → Strategy → Pattern → Reference implementation → Delivery requirement → Test**

## Phase 1 — Foundations

Create the controls before changing the public argument.

Deliverables:

- tectonic integration register;
- tectonic-honesty position paper;
- migration plan;
- governing-principle refinements;
- publication-architecture changes;
- limited Part I changes where the architectural-platform definition needs to widen.

Exit condition: the project has a stable vocabulary for permanence, movement, attachment, manufacture and honesty.

## Phase 2 — Architecture of reversible assembly

Rewrite the relevant Part II chapters around the new logic.

Primary work:

- Chapter 6: bounded movement; functional decomposition of interfaces; tectonic honesty;
- Chapter 10: boundary independence of replaceable layers;
- Chapter 11: rename and rebuild as **The Replaceable Interior**;
- Part V/publication architecture: manufacture according to lifespan;
- strengthen the catalogue-wide methodology.

Exit condition: the new ideas exist as a coherent architectural argument before project-specific solutions are selected.

## Phase 3 — Pattern development

Create a candidate-pattern document rather than prematurely promoting speculative systems into the established Core 12.

Initial candidates:

1. **Seated Floor Structure**
2. **Architectural Backplane**
3. **Replaceable Wall Lining**
4. **Finish-Agnostic Floor Platform**

Also strengthen Core Pattern 08 — Movement / Slip Junction.

Every candidate must include:

- problem;
- forces;
- proposition;
- structural/boundary obligations;
- permanent-fabric impact;
- architectural resolution;
- assembly/replacement sequence;
- evidence status;
- failure modes;
- research/prototype requirements;
- reference-house direction.

Exit condition: each physical idea is clear enough to be challenged by an architect, structural engineer, MEP engineer, fabricator and building physicist.

## Phase 4 — Reference-house tectonic language

Create a project-specific architectural-language document.

Develop:

- Georgian interface grammar;
- skirting, dado, picture rail, cornice, architrave, panel moulding and threshold as real assembly interfaces;
- restrained brass/bronze vocabulary;
- panel-joint composition;
- material ageing and patina;
- rules separating universal doctrine from reference-house taste.

Exit condition: technical reversibility no longer implies an industrial or access-panel aesthetic.

## Phase 5 — Manufacturing strategy

Develop the construction hierarchy:

1. site-built permanent structure and enduring envelope;
2. semi-permanent interface infrastructure;
3. manufactured replaceable architectural assemblies;
4. commodity technical components.

Working proposition:

> **Build the permanent house. Assemble the changeable house inside it.**

Add the presumption:

> **The shorter-lived and more replaceable the layer, the stronger the presumption that it should be manufactured under controlled conditions and dry-assembled on site.**

This remains a presumption, not an absolute rule.

## Phase 6 — Delivery enforcement

Update the RIBA implementation brief with:

- permanence map;
- attachment map;
- movement map;
- assembly hierarchy;
- manufacturing schedule;
- interface-family schedule;
- wet-trade justification;
- replacement-sequence drawings;
- first-article disassembly and reinstatement;
- prototype acceptance criteria.

Exit condition: the philosophy can survive appointment, technical design, procurement and construction.

## Phase 7 — Engineering and prototype programme

Do not promote the four candidate systems until they survive focused technical work.

### Seated floor
Test bearing, wall restraint, diaphragm action, joist stability, robustness, fire, acoustics and movement.

### Architectural backplane
Test load classes, anchor strategy, modular geometry, corrosion, conflicts with services, exceptional loads and future remanufacture.

### Replaceable wall lining
Test fire, acoustic performance, impact resistance, moisture, fixing loads, panel handling, tolerances, corners, openings and surface quality.

### Floor platform
Test stiffness, rattle/squeak, impact sound, airborne sound, tile/stone cracking, weight, underfloor heating, lifting, thresholds and local replacement.

Target 1:1 prototypes:

1. complete wall bay;
2. floor bay with interchangeable finish systems;
3. wall/floor/joist edge;
4. wall/ceiling cornice-slip junction.

Prototype review must include removal and reinstatement.

## Phase 8 — Traceability and hardening

Use the integration register as a final audit.

Check that:

- Georgian-specific decisions have not leaked into universal doctrine;
- brass is functional rather than thematic;
- “few fixings” has not become “no fasteners”;
- “wet-trade discipline” has not become a blanket plaster ban;
- “bounded movement” has not weakened required restraint;
- replaceability has not compromised boundary performance;
- panelisation has not become an aesthetic obligation;
- experimental patterns are labelled honestly;
- every unusual repeated detail has a responsible designer and prototype/test route.

Only after this pass should the project consider whether a consolidated Doctrine v8 snapshot is useful.
