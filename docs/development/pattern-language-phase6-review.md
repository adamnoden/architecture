## 2.2 New identities admitted for canonical migration

The following propositions pass the pattern admission test strongly enough to receive stable IDs in Phase 7. Their evidence labels remain independent.

### Ground-Supported Façade Access

**Evidence:** Supported  
**Why admitted:** already developed to full pattern anatomy; clear site/ground/façade relationship and task-specific proportionality.

### Accessible Vertical Service Zone

**Evidence:** Supported direction  
**Why admitted:** strong recurrence/context/forces/variation; Phase-5 whole-house run proved the pattern useful without assuming every dwelling needs a commercial riser.

### Accessible Room Service Route

**Evidence:** Supported direction  
**Why admitted:** consolidates skirting and vertical joinery routes into one stronger room-scale invariant: local distribution occupies removable architectural layers rather than permanent fabric.

### Compartmented Service Void

**Evidence:** Established boundary principle / Supported architectural pattern  
**Why admitted:** recurring relationship is clear—open void stops at a boundary while individual services cross deliberately. It integrates fire, acoustic and pest consequences rather than restating a single compliance clause.

### Visible Leakage Path

**Evidence:** Established/supporting overseas regulatory precedent  
**Why admitted:** strong physical invariant and unusually direct precedent: credible concealed leakage is deliberately brought to a safe legible point where it becomes visible.

### Failure-Tolerant Wet Service Room

**Evidence:** Supported  
**Why admitted:** utility/laundry/service rooms create a recurring room-scale problem involving water appliances, isolation, containment, drainage/drying and maintenance. The pattern is broader than one tray or sensor product.

### Permanent Opening / Replaceable Door

**Evidence:** Supported / mature practice  
**Why admitted:** shares lifespan logic with the window pattern but has materially different adjustment, wear, security, acoustic/privacy and repeated-use forces.

### Designed Threshold

**Evidence:** Supported / mature interface practice  
**Why admitted:** thresholds recur where floor assemblies, movement, wear, accessibility and—in external conditions—weathering/drainage meet. Internal and external variants remain one interface family unless migration proves otherwise.

### Source-Capture Bathroom Extract

**Evidence:** Established ventilation principle / Supported architectural pattern  
**Why admitted:** moisture is generated at a concentrated source; terminal geometry, transfer air, duct route, fan location, noise and maintenance create a recurring relationship materially distinct from kitchen grease extraction.

### Controlled Attachment Plane

**Evidence:** Supported direction  
**Why admitted:** merges `Architectural Backplane` and `Fixing Infrastructure` around a clearer invariant: repeated faster-changing fit-out attaches primarily to a durable, load-classified interface rather than repeatedly consuming permanent fabric. Specific rail/backplane constructions remain implementation families.

Phase 7 will assign stable IDs sequentially after `HSA-P-012`; `HSA-P-006` remains permanently retired.

# 3. Held pattern candidates — do not assign stable IDs yet

These propositions remain useful but should stay outside the canonical migration set until their stated gate is crossed.

## Replaceable Architectural Lining

Conceptually passes the admission test, but the proposition can still fail the project's central **repose/solidity** requirement. Keep as a candidate until the full wall-bay prototype compares it against first-rate plaster and ordinary drylining.

## Individually Isolatable Manifold Distribution

Credible network pattern with mature precedent, but the audit has not yet shown that it belongs in the **architectural** language rather than the services implementation layer across enough domestic systems. Keep candidate status.

## Local Deep Service Zone

Useful coordination tactic where bulky/gravity services would otherwise deepen a whole storey. Hold until several worked conditions show a stable invariant beyond “make more space locally”.

## Selective Floor Access / Selective Accessible Floor Zone

Potentially stronger and more proportionate than full-room access flooring, but domestic acoustic/tactile value and repeatable geometry remain unresolved. Keep tied to the floor prototype programme.

No stable HSA pattern number is created merely to remember these ideas.

# 4. Strategies — preserve, but keep out of the pattern graph

## Fail-Safe Water Distribution

This absorbs the durable content of retired `HSA-P-006 Water-Damage-Safe Service Route`.

It is a strategy because its valid physical responses differ materially by route and risk:

- accessible joints;
- joint-minimised/continuous runs;
- visible leakage paths;
- pipe-in-pipe;
- local containment;
- automatic isolation;
- wet-room containment;
- inspectable drainage.

The strategy can invoke patterns without pretending they are one solution.

## Decompose Structural Interface Functions

Extracted from `Seated Floor Structure`:

> distinguish gravity support, restraint, diaphragm transfer, movement and boundary obligations rather than collapsing them into an undifferentiated fixed joint.

This is currently a structural/design strategy, not a pattern.

## Separate Structural Floor from Changeable Layers Where Proportionate

Extracted from `Finish-Agnostic Floor Platform`.

This strategy can support future accessible-floor patterns or ordinary conventional floors. It does not require a removable platform.

# 6. Old publication slots explicitly rejected as canonical patterns

## Perimeter Dry Zone

**Do not migrate.**

The slot bundled splashback control, drainage, drying, inspection and maintenance-support territory. These functions can conflict. Historic England explicitly notes that some gravel/French-drain arrangements near foundations can concentrate water at wall bases.

Relevant concerns remain owned by:

- Accessible Rainwater Route;
- Ground-Supported Façade Access;
- envelope/moisture design;
- project-specific landscape/drainage strategy.

A sharper wall-base pattern may emerge later, but this catalogue placeholder does not earn preservation.

## Generic Floor Access

**Do not migrate as currently named.**

Access is an outcome, not enough of an invariant. Keep Selective Floor Access as a held candidate tied to physical floor research.

# 7. Resulting language shape

After Phase 7, the active canonical language should contain **21 pattern identities** if no migration-level contradiction appears:

- 11 surviving existing identities;
- 10 new admitted identities;
- one permanently retired historical ID (`HSA-P-006`).

The number 21 has no design significance and is not a target. It is simply the consequence of the audit.

This is a substantial simplification relative to the old 30-slot inventory because:

- duplicate concepts are merged;
- strategies are no longer disguised as patterns;
- implementation families are no longer promoted by naming;
- weak candidates are allowed to remain candidates;
- one overloaded water pattern becomes a cleaner strategy plus specific patterns/implementations.

# 8. Phase-7 migration order

Do not perform the migration as one destructive rewrite.

## P7.1 — establish new canonical index and identity map

Create one generated/browsable language index from pattern frontmatter. Record active, candidate and retired states without creating a second source-of-truth registry.

Assign IDs to the ten new admitted patterns. Keep `HSA-P-006` retired.

## P7.2 — migrate surviving existing patterns individually

Split `core-12.md` into canonical individual pattern pages while preserving provenance and links.

For each:

- preserve evidence/maturity honestly;
- add context and language relationships only where useful;
- add formalisation boundary;
- avoid expanding prose merely to fill a template;
- redirect/replace old aggregate navigation only after all migrated pages exist.

`HSA-P-003` receives its scope/name correction during this step.

`HSA-P-006` becomes a retired-pattern pointer to the water strategy, not a rewritten pattern pretending identity survived.

## P7.3 — migrate/admit the ten new patterns

Use developed source material where it exists; do not fabricate evidence for thin publication placeholders.

The new patterns should be individually reviewable and reversible.

## P7.4 — normalise non-pattern material

Move/retitle material only after replacement destinations exist:

- water strategy;
- structural-interface strategy;
- floor-layer strategy;
- implementation-family records;
- held-candidate pages.

Research/prototype evidence remains in place and is cross-linked rather than duplicated.

## P7.5 — reconcile publication inventory

Only after the canonical language exists:

- replace the old 30-slot Part-III inventory;
- group patterns for reading without encoding taxonomy into IDs;
- add sequence/map material where it improves use;
- keep Part II as architectural argument.

## P7.6 — lightweight tooling

After stable frontmatter exists across the canonical set, add only useful automation:

- ID uniqueness;
- broken relationship references;
- reverse links;
- filters by scale/domain/evidence;
- orphan-pattern warnings.

Do **not** build a D3 graph merely because metadata exists.

# 9. Phase-7 acceptance criteria

Phase 7 passes only if:

1. every active pattern has exactly one canonical page;
2. every stable ID is unique and never silently changes meaning;
3. `HSA-P-006` remains visibly retired rather than disappearing from provenance;
4. strategies and implementation families have clear homes outside the pattern graph;
5. held candidates remain visibly non-canonical;
6. no research/evidence record is rewritten into false certainty;
7. pattern relationships remain sparse and useful;
8. sequences remain separate from graph relationships;
9. Reference House occurrences point to canonical pattern identities without becoming evidence for them;
10. VitePress navigation/build passes;
11. the publication no longer promises obsolete catalogue slots;
12. the resulting structure is easier to understand than the pre-migration repo.

If the migration makes navigation or authorship more bureaucratic, stop and simplify before merging.

---

# 10. Formal Phase-6 decision

**PASS. Phase 7 canonical migration is authorised under the staged order above.**

The audit itself is now the authority for classification during migration. If Phase 7 discovers a genuine contradiction, update this review explicitly rather than quietly changing identity in the migrated page.

The next checkpoint should be a **Phase-7 migration plan/branch with the identity map and file layout**, followed by small coherent migration commits—not immediate publication polish.
