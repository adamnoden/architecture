# Resolved-work sanitation audit

**Programme:** PUB-SAN / issue #133  
**Governing rule:** **The publication contains the resolved work, not the history of its resolution.**  
**Current state:** SAN-00 and SAN-01 complete; SAN-02/SAN-03 substantially complete; SAN-04 execution substantially complete; SAN-05 first-reader traversal nearing completion; SAN-06 remains.

Losslessness means preservation of architectural ideas, evidence, constraints and useful distinctions—not preservation of draft chronology, migrations, gate names or superseded formulations on reader-facing surfaces.

## Public/internal boundary

The website and PDFs now have an explicit public/internal boundary.

- Repository ownership no longer implies publication.
- VitePress excludes internal development/history records from the public build.
- Navigation is filtered through the same boundary.
- The Working Edition and Primer use explicit publication manifests.
- Internal records remain recoverable in the repository and Git history.

The reader-facing corpus therefore presents the current intellectual product while the repository can continue to retain audits, handoffs, stage records and development evidence.

- **G-01 Validation and Limits**;

## Computational track

The computational public surface has now been separated into **resolved concepts/capabilities** versus **historical paper/fixture/family research**.

### Reader-facing core

The following pages have been rewritten in resolved present tense:

- **Executable Architecture** — semantic authoring/compiler proposition, obligations, proof boundary and current executable scope;
- **Formal Architectural Model** — stable identity, overlapping spatial/structural/boundary/service/lifecycle/evidence graphs and current semantic scope;
- **Validity and Obligations** — authority-bearing validity dimensions, epistemic states, obligation discharge and release/physical-conformance distinction;
- **Evidence and Provenance** — scoped evidence, dependencies, invalidation, time-phased evidence and design/physical/in-use distinction;
- **Compiler Targets** — normative target identity separated from supported domain, grammar and project configuration;
- **Structural Semantics** — physical fabric vs topology vs analytical proof, with explicit current no-capacity boundary;
- **Boundary Semantics** — independent weather/air/thermal/moisture systems and typed opening/penetration transitions without pretending topology proves physics;
- **Interface Obligation Bundles** — authoring relationships contribute to shared domain graphs from which canonical obligations are derived, rather than concatenating checklists;
- **Supported Domain** — the compiler’s present competence boundary and the rule that unsupported is neither invalid nor proven;
- **Prior Art and Research Context** — IFC/openBIM, IDS, ontologies, compliance checking, grammars, Space Syntax, pattern languages, floor-plan generation and parametric platforms without broad novelty claims.

The current computational overview remains the authority for demonstrated capability: bounded plan semantics, qualitative structure, services, boundary topology, selected versioned numeric methods and deterministic inspection outputs. It does not claim structural capacity, building-physics adequacy, fire/acoustic adequacy, MEP sizing or whole-building regulatory compliance.

## Semantic guardrail

Identifiers are judged by function, not appearance.

- `G-01 v0.1` remains because it names a current formal specification.
- stable pattern IDs remain because they support current cross-reference.
- current compiler/model identities remain where they describe active semantics or deterministic outputs.
- standards/regulatory identifiers remain where relevant.
- development-stage labels do not survive merely because the project once used them.

Before any source is internalised, its unique architectural claims, distinctions, constraints, evidence and useful formulations are mapped to a current owner.
